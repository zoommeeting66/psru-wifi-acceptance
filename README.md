# ระบบสนับสนุนการตรวจรับเครือข่าย Wi‑Fi 1,000 จุด

ระบบช่วยเก็บและควบคุมหลักฐานการตรวจรับงานติดตั้งเครือข่ายไร้สาย 1,000 จุด
ช่างภาคสนามบันทึกผลตรวจและถ่ายรูปหลักฐานผ่านมือถือ **โดยไม่ต้องมีสัญญาณ**
คณะกรรมการตรวจรับติดตามความคืบหน้า จัดการข้อบกพร่อง (NCR) และออกเอกสารสรุปเสนอลงนาม

> **ระบบไม่ตัดสินผลการตรวจรับแทนคณะกรรมการ**
> ระบบรายงานเพียง *ค่าที่วัดได้เทียบกับเกณฑ์ที่อ้างอิงจาก TOR/สัญญา* และชี้จุดที่ต่ำกว่าเกณฑ์
> การตรวจรับตามกฎหมายเกิดจากการลงนามของคณะกรรมการเท่านั้น

---

## หลักการออกแบบที่เป็นแกนของระบบ

เรียงตามความเสียหายที่จะเกิดถ้าพัง

1. **ไม่มีที่ใดในระบบบอกว่าจุดใด "ผ่าน" หรือ "ไม่ผ่าน" การตรวจรับ** — คำว่า `หลักฐานครบ` หมายถึงหลักฐาน 6 ประเภทครบเท่านั้น
2. **ผลตรวจเป็นบันทึกแบบเพิ่มอย่างเดียว และทำซ้ำได้ (idempotent) ตาม `clientUuid` ที่มือถือสร้าง** — มือถือที่ส่งคิวออฟไลน์ซ้ำจะไม่มีวันสร้างข้อมูลซ้ำ และไม่มีวันเขียนทับผลที่อยู่บนเซิร์ฟเวอร์แล้ว สถานะของจุดเป็นค่าที่ *คำนวณ* ไม่ใช่ค่าที่เก็บไว้
3. **ผลตรวจที่เข้าคิวแล้วจะไม่หายเงียบ** — ส่งไม่สำเร็จจะถอยเวลาแล้วลองใหม่ ไม่ลบทิ้ง และช่างเห็นตลอดว่าค้างส่งกี่รายการ
4. **การปิดข้อบกพร่องต้องอ้างอิงผลตรวจซ้ำที่มีหลักฐานแนบ** อยู่จุดเดียวกัน และเกิดขึ้นหลังการเปิดข้อบกพร่องนั้น — ช่างภาคสนามปิด NCR ของตัวเองไม่ได้โดยตั้งใจ
5. **ไม่มีการตัดข้อมูลทิ้งเงียบ ๆ** — ต้นแบบเดิมที่ระบบนี้มาแทน แสดงเพียง 300 จุดแรกจาก 1,000 จุด ซึ่งเท่ากับซ่อนข้อมูลจากคณะกรรมการ

## เทคโนโลยี

| ส่วน | ใช้ |
|---|---|
| Backend | Node.js, Express 4, TypeScript (strict), Prisma 5 |
| ฐานข้อมูล | PostgreSQL 17 |
| Frontend | ES modules ล้วน เสิร์ฟตรงจาก `public/` — **ไม่มี bundler ไม่มี build step** |
| ออฟไลน์ | Service Worker + IndexedDB outbox |
| เอกสาร | pdfmake ฝังฟอนต์ Sarabun (ภาษาไทยไม่แตก) |
| ทดสอบ | Vitest + Supertest + fake-indexeddb — 99 tests |

ฟอนต์ทั้งหมด self-host ไม่มี CDN เพราะอุปกรณ์ภาคสนามอาจไม่มีเน็ต

---

## ติดตั้งและใช้งาน

```bash
npm install
cp .env.example .env          # แล้วแก้ค่าให้ตรงกับเครื่องคุณ
createdb psru_wifi            # และ psru_wifi_test สำหรับรันเทสต์
npx prisma db push && npx prisma generate
npm run db:seed
npm run dev
```

- เดสก์ท็อป (กรรมการ): `http://localhost:3200/`
- มือถือ (ช่างภาคสนาม): `http://localhost:3200/m`

รันเทสต์: `npm test`

### บัญชีเริ่มต้น

| ชื่อผู้ใช้ | บทบาท | ทำอะไรได้ |
|---|---|---|
| `admin` | ผู้ดูแลระบบ | ทุกอย่าง |
| `committee` | กรรมการตรวจรับ | ดูผล ปิด NCR สร้างแผน ออกรายงาน |
| `field1`, `field2` | ช่างภาคสนาม | บันทึกผลตรวจผ่าน `/m` |

รหัสผ่านเริ่มต้นกำหนดไว้ใน `prisma/seed.ts` — **ต้องเปลี่ยนก่อนใช้งานจริง**
บทบาท `FIELD` ไม่มีสิทธิ์ปิด NCR และ `COMMITTEE` ไม่มีสิทธิ์บันทึกผลตรวจ โดยตั้งใจ

## หน้าจอ

**เดสก์ท็อป** — ภาพรวม · ทะเบียนจุดติดตั้ง (แบ่งหน้าจริง ไม่ตัดทิ้ง) · แผนตรวจรายวันพร้อม Gate 4 ขั้น · บอร์ดข้อบกพร่อง · รายงานและส่งออก CSV/PDF

**มือถือ (`/m`)** — รายการจุดของวันนี้ · ฟอร์มบันทึกผลหน้าเดียวพร้อมช่องถ่ายรูปหลักฐาน 6 ประเภท · แถบแสดงจำนวนที่ค้างส่ง

รูปถูกย่อในเครื่องเหลือด้านยาว 1600px ก่อนเข้าคิว เพื่อไม่ให้ IndexedDB บวมจนเบราว์เซอร์ล้างข้อมูลทิ้ง

## สถานะ

ใช้งานได้ครบทุกฟังก์ชัน ผ่านการทดสอบวงจรออฟไลน์ทั้งวงจรจริง (บันทึกขณะไม่มีเน็ต → ส่งเมื่อสัญญาณกลับมา → กดส่งซ้ำแล้วข้อมูลไม่ซ้ำ)

ยังมีรายการที่ควรแก้ก่อนใช้งานภาคสนามจริง เช่น ตรวจสอบขอบเขตเวลาของ `inspectedAt`
ความทนทานของ service worker ตอนเปิดครั้งแรกแบบออฟไลน์ และการจำกัดอัตราการล็อกอิน

เกณฑ์ตัวเลขใน `prisma/seed.ts` เป็น **ค่าตัวอย่าง** ต้องแก้ให้ตรงกับ TOR/สัญญาจริงก่อนใช้ตรวจรับ
